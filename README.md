# Week 05 Friday — EDA Assessment: Support Tickets

Full exploratory analysis of a deliberately corrupted support-ticket dataset:
**load → measure every problem → fix with written justification → visualize → report.**

## Dataset

`tickets_raw.csv` — 4,012 rows × 6 columns (`ticket_id`, `created_at`, `agent_id`,
`priority`, `resolution_hours`, `channel`), generated by the provided
`generate_data.py` (4,000 tickets + planted mess).

## Problems found (measured on the raw file, before any fix)

| Issue | Count | % of rows | Fix applied | Why not the alternative |
|---|---:|---:|---|---|
| Missing `agent_id` | 121 | 3.02% | kept as NaN | IDs cannot be invented; field unused in analysis |
| Missing `channel` | 193 | 4.81% | explicit `"Unknown"` category | mode-fill would fabricate ~140 Chat tickets; dropping hides the gap |
| Exact duplicate rows | 12 | 0.30% | dropped, `keep="first"` | byte-identical appends; keeping double-counts tickets |
| Negative `resolution_hours` | 25 | 0.62% | `abs()` recovery | magnitudes verified plausible (3.0–37.8 h) → sign-entry error; dropping destroys recoverable truth; median-imputing fabricates when truth is recoverable |
| Sentinel `999` hours | 15 | 0.37% | NaN → priority-group median, audit trail printed | capping invents fake values; only exact-999 removed — legitimate long tail survives |
| Priority casing (`high`/`High`) | 982 | 24.48% | `str.capitalize()` + domain assert | dropping 24.5% of data to fix a label is disproportionate |

## Key results

1. **Raw data overstated workload ~29%** — mean 15.56 h raw vs 12.03 h cleaned.
2. **Casing split silently undercounted High priority by ~49.6%** until normalized.
3. **No meaningful speed difference between priorities** (means 11.79–12.21 h,
   overlapping CIs) — reported as a null result rather than a invented trend.
4. **Process stable across Mar–Apr 2024** (trend slope ≈ +0.00004 h/ticket).

## Limitations (honest)

- `abs()` assumes pure sign flips; per-row proof requires the source system.
- The 15 imputed durations are priority-medians (estimates), ticket IDs printed in §3.5.
- 120 missing agent IDs are unrecoverable without CRM backfill.
- `findings.json` measures the delivered raw file, duplicates included (divergence
  quantified in notebook §2.5: exactly one record).
- Conclusions cover two months only; re-run on rolling windows before generalizing.
